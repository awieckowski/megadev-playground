Parser: dates are read month first

The shared parser treats numeric dates as month/day even when a tenant writes day/month. The result is a month/day swap. For example, R-41200 is an app report from harbour.dental (en-GB, booking-v2): a 7 April reminder went out on 4 July.

The supplied classifier assigns this cause to day-first tenants on app and email, and to forms other than the booking-v3 hint path. Fix the parser using the tenant’s date convention; test ambiguous dates, invalid dates, and day-first/month-first controls. Do not infer that any fix has shipped from the word “queued.”

Hint: booking-v3 tells people the wrong input format

The booking-v3 field prints MM/DD/YYYY, but reads the value using the day-first tenant’s format. People follow the hint and their booking lands on the wrong date. This is a different path and needs its own fix: generate the hint and input handling from the same tenant convention.

For example, R-41230 is a form report from copper.studio (es-ES, booking-v3). Intake tagged it parser, but the tenant/form/channel combination classifies it as hint. The affected form tenants in this export are alder.physio, copper.studio, and pale.harbour. Test them separately from app/email paths and booking-v2.
